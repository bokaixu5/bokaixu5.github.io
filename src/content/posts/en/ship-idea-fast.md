Most ideas fail not because they are weak, but because the first version ships too late.

My current rhythm is fixed: `4h to define the problem + 12h to build a working slice + 24h to collect feedback + 8h to refine`.

## 1. Define the problem

- Who is the user?
- Is the pain point frequent and concrete?
- What outcome would count as success?

If I cannot answer these clearly, I do not start building.

## 2. Build a minimal loop

Version one keeps exactly one success path:

- one input channel
- one core processing path
- one visible output

Anything "nice to have" is postponed.

## 3. Iterate from friction

I ask 3-5 real users to try the product and capture where they get blocked. Then I only make two kinds of changes:

1. shorten time-to-value
2. improve clarity at critical steps

These changes usually move retention more than adding features.
